Data sources & connection settings — open this if nothing loads

Run it properly: the SEC does not send CORS headers, so a browser opening this file straight off disk has to bounce requests through a public proxy — those rate-limit and go down, and they mangle EDGAR's responses. Next to this file is serve.ps1; the launcher starts it for you, or run:

powershell -ExecutionPolicy Bypass -File serve.ps1

It serves this page at http://localhost:8787/ and fetches data from the same origin, so CORS never applies. Nothing to install — Windows PowerShell only.

Every financial figure here comes from SEC EDGAR — the XBRL data companies actually file, going back 15+ years. US filers only; a company must file with the SEC to appear at all. Search runs against the SEC's own filer list, so it can only ever offer companies that have filings behind them.

Cash-flow lines are filed year-to-date, so quarterly figures are recovered by differencing consecutive periods within each fiscal year; a value marked derived in the tooltip came out of that subtraction rather than a directly filed 3-month figure. Companies also retire and adopt XBRL tags over time, so each line is stitched from several tags — the definition behind the oldest bars can differ slightly from the newest. EBITDA has no XBRL tag of its own and is reconstructed as operating income + D&A, so it will not match a company's own "adjusted EBITDA".

Two things do not come from EDGAR, because the SEC publishes what companies report — not what the stock trades at, and not what anyone expects next.

The share price is fetched from Yahoo. Market cap, EV, trailing P/E, P/S, EV/EBITDA and net debt are all that price measured against TTM figures from the filings.

The forward P/Es and PEG rest on sell-side analyst consensus EPS estimates, also from Yahoo. These are forecasts, not reported facts: they get revised, they are routinely too optimistic, and for thinly covered companies they may represent only a handful of analysts. PEG is the forward P/E divided by the estimated growth rate for that year, so it inherits the same uncertainty twice over. Treat the trailing figures as measured and the forward ones as opinion. If either is unavailable the tile reads n/m and everything else still works.
